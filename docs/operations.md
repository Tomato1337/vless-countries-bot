# Эксплуатация

## Права доступа

Владелец задаётся через `TELEGRAM_OWNER_ID`.

Владелец может:

- добавлять и удалять exits;
- выполнять `/sync`;
- управлять trusted users;
- создавать пользователей (`/adduser`, кнопка `Add user`);
- привязывать профили к trusted users и видеть все ключи URnetwork;
- добавлять прокси себе, всем или выбранным профилям;
- использовать NordVPN Repair.

Trusted users могут управлять exits и выполнять `/sync`, но не могут изменять
allowlist и создавать пользователей. Если владелец привязал к trusted-админу
профиль, тот редактирует ключ URnetwork и прокси этого профиля.

Бот принимает управляющие команды только в личном чате.

## Команды

```text
/start
/countries
/nord
/set usa <vless://...>
/remove usa
/sync
/allow <telegram-id>
/deny <telegram-id>
/trusted
/adduser <name>
/proxies
```

| Команда | Назначение |
| --- | --- |
| `/start` | Открыть кнопочное меню. |
| `/countries` | Показать созданные exits. |
| `/nord` | Добавить NordVPN-регион через кнопки. |
| `/set` | Добавить или обновить ручной VLESS exit. |
| `/remove` | Удалить exit после подтверждения. `ch-zurich` удалить нельзя: на него перенаправляется torrent-трафик. |
| `/sync` | Добавить недостающие профили для новых `subId`. |
| `/allow` | Разрешить доступ Telegram ID. Только владелец. |
| `/deny` | Отозвать доступ Telegram ID и снять привязку профиля. Только владелец. |
| `/trusted` | Показать админов панели с именем, `@login` и привязанным профилем. Только владелец. |
| `/adduser` | Создать подписку `subId=<name>` с профилями `<name>-pc`, `<name>-phone`, `<name>-russia` и профилями всех exits; прислать ссылку подписки. Только владелец. |
| `/proxies` | Прокси URnetwork и свои прокси как отдельные профили подписки. |

## Профили russia

`<subId>-russia` выходит в интернет напрямую с RU-сервера. Маршрут задаёт не
бот, а правило панели `user: ["regexp:.*-russia$"]` → `direct`, стоящее выше
правила `in-443-tcp` → GE. `/sync` создаёт недостающий `<subId>-russia` для
каждой подписки и отказывается это делать, если такого включённого правила с
существующим outbound в шаблоне нет. Russia-профили не записываются в SQLite
бота и при удалении exits не трогаются.

## Добавление NordVPN-региона

1. Откройте `/nord`.
2. Выберите страну.
3. Выберите город.
4. Запустите автоматический подбор или выберите hostname вручную.
5. Бот протестирует candidate outbound.
6. После успешного теста бот обновит Xray-template и создаст профили подписок.

Можно добавить несколько регионов одной страны:

```text
🇺🇸-ilya-us-chicago
🇺🇸-ilya-us-new-york
```

Уже занятый регион помечается в кнопочном интерфейсе.

## Repair

Кнопка `Repair` доступна только для NordVPN-регионов.

Repair:

1. Повторно получает список NordVPN hostname нужного города.
2. Сначала тестирует наиболее загруженные альтернативы: наименее загруженные
   серверы NordVPN часто простаивают, потому что не работают.
3. Сохраняет первый рабочий outbound.
4. Не меняет UUID пользовательских профилей.
5. Перезапускает Xray через штатный endpoint 3x-ui.

Каждый выбор hostname (при добавлении региона и при Repair) записывается в SQLite
(`nordvpn_server_selections`: страна, город, hostname, время). В карточке региона
показывается `Selected`, а в списках серверов — `🕓` с временем последнего выбора
каждого hostname (МСК).

Для ручного VLESS exit используйте повторный `/set`.

## Разделение ownership

Бот изменяет только:

- outbounds с префиксом `countries-` и `proxies-`;
- routing rules с префиксом `countries-` и `proxies-route-`;
- UUID клиентов, записанные самим ботом в SQLite.

Slug exit не может оканчиваться на `-proxy`: этот суффикс занят профилями
прокси, чтобы правила exits `regexp:.*-<slug>$` их не перехватывали.

Бот не изменяет:

- старые device-профили и профили `-russia`;
- Germany outbound;
- одиночный `nord-...` outbound, созданный вручную в UI панели;
- неизвестные routing rules и outbounds.

NordVPN exit нельзя перезаписать ручным `/set`, и наоборот.

## Прокси (URnetwork и свои)

Раздел `Proxies` (`/proxies`) добавляет в подписку отдельный профиль, который
выходит в интернет через прокси: `🇩🇪-ilya-ur-de-proxy`, `🇳🇱-ilya-nl-home-proxy`.
Маршрут `RU -> GE -> прокси`: outbound прокси использует `dialerProxy` на Germany.

- **URnetwork ([ur.io](https://ur.io/docs/hosted-proxies))**: у каждого профиля
  свой ключ URnetwork, и прокси создаётся на аккаунте этого профиля через Operator
  API (`POST /network/auth-client`). HTTPS работает на любом тарифе (только TCP),
  SOCKS5 передаёт и UDP, но требует UR Pro. При удалении прокси-профиля бот
  удаляет и hosted proxy на ur.io. Бесплатный тариф: до 5 активных прокси на аккаунт.
  Локация: `Best available` (любой провайдер сети, профиль `🌐-ilya-ur-best-proxy`)
  или страна. Галочка `Unique exit IP` (UR Pro) даёт прокси выходной IP, который
  не используют другие unique-exit прокси аккаунта (суффикс `-uniq`); город
  выхода показывается в карточке прокси. Кнопка `🔄 Сменить IP` в карточке
  такого прокси создаёт на ur.io новый hosted proxy, пока старый ещё держит свой
  выход (поэтому IP гарантированно другой), переключает outbound и удаляет
  старый. Клиент 3x-ui, ссылка подписки и IPv6 GE не меняются; если новый выход
  не прошёл тест, остаётся старый.
- **Свой прокси**: URL `socks5://user:pass@host:port`, `http://host:port` или
  `https://user:pass@host:port`. Сообщение с URL бот удаляет из чата.

Владелец выбирает, кому добавить прокси: себе (привязанный к нему профиль),
всем профилям или отмеченным. Для URnetwork профили без ключа пропускаются и
перечисляются в отчёте. Каждый прокси тестируется через `testOutbounds` в режиме
`http` до применения: временный Xray выполняет HTTP-запрос по полной цепочке
`RU -> GE -> прокси`, включая авторизацию. Режим `tcp` не используется: он проверяет
прямое соединение из RU и игнорирует `dialerProxy`. Непрошедшие прокси пропускаются,
остальные применяются одним обновлением шаблона с полным rollback при ошибке.

## Профили и ключи URnetwork

`Profiles` (только владелец) показывает все подписки, их ключи URnetwork,
редакторов и число прокси. В карточке профиля ключ виден целиком; там же его
можно задать, заменить или удалить. Принимается API-ключ `urn_...` или
одноразовый auth code со страницы `https://ur.io/app/account/settings`: бот
обменяет код на постоянный API-ключ и проверит его. Сообщение с ключом бот
удаляет.

Если у профиля нажавшего `+ URnetwork` нет ключа, бот сразу предлагает его
добавить: trusted-админ попадает в ввод ключа и после сохранения продолжает к
выбору локации; владелец может добавить ключ или продолжить без него. Заменить
ключ позже: `Proxies` → `🔑 Ключ URnetwork` (у владельца `🔑 Мой ключ URnetwork`).

Как получить ключ: войти на ur.io, открыть
[Account → Settings](https://ur.io/app/account/settings), создать Auth code и
отправить его боту.

## Привязка профиля к админу панели

`Trusted users` показывает имя, `@login`, Telegram ID и привязанный профиль
каждого, у кого есть доступ к панели, включая владельца. Имя обновляется при
каждом обращении к боту; для тех, кто ещё не писал боту после обновления, бот
запрашивает его через `getChat`. В карточке пользователя владелец привязывает
или отвязывает профиль. Trusted-админ с привязанным профилем меняет ключ
URnetwork и добавляет или удаляет прокси только этого профиля.

## Safe apply

При добавлении или замене exit:

1. Бот получает актуальный Xray-template.
2. Проверяет наличие Germany outbound.
3. Собирает candidate outbound.
4. Вызывает `/panel/api/xray/testOutbounds`.
5. Сохраняет redacted backup template в SQLite.
6. Обновляет Xray-template.
7. Панель применяет Xray-template и перезапускает работающий Xray.
8. Создаёт недостающие подписочные профили.

При ошибке бот выполняет компенсирующий rollback. Backup остаётся в SQLite для
ручной диагностики.

## Smoke-test после добавления

После первого добавления региона:

1. Обновите подписку клиента.
2. Убедитесь, что появился профиль вида `🇨🇿-ilya-cz-prague`.
3. Подключитесь к новому профилю.
4. Проверьте внешний IP.
5. Откройте несколько обычных сайтов.
6. Проверьте загрузку файла больше `1 MiB`.
7. Переключитесь на старый device-профиль и убедитесь, что он всё ещё выходит
   через Germany.

## Диагностика

| Симптом | Вероятная причина | Действие |
| --- | --- | --- |
| `Compatibility check failed` | Неверный URL, логин, пароль, inbound ID или GE tag. | Запустите `docker compose run --rm bot bun index.ts --check`, затем проверьте `.env`. |
| HTTPS certificate error | Панель использует недоверенный сертификат. | Установите сертификат доверенного CA и проверьте полный `XUI_BASE_URL`. |
| В UI outbound есть, но IP остаётся Germany | Xray-template сохранён, но runtime не перезапущен либо профиль старый. | Обновите образ бота, выполните Repair и переподключите профиль. |
| IP нужной страны виден, но страницы висят в `pending` | Потеря UDP framing или слишком большой MTU во вложенном NordLynx chain. | Убедитесь, что outbound содержит `transportLayer: true`, `noKernelTun: true`, `mtu: 1280`; затем Repair. |
| Высокая задержка NordVPN | Перегруженный или далёкий hostname. | Выполните автоматический Repair либо выберите hostname вручную. |
| Новый пользователь не получил профиль | Новый `subId` ещё не синхронизирован. | Выполните `/sync`. |
| `/sync` сообщает collision | Два `subId` нормализуются в одинаковый slug. | Переименуйте один `subId` в панели и повторите `/sync`. |
| NordVPN menu disabled | Не задан или неверен `NORDVPN_PRIVATE_KEY`. | Проверьте base64 private key в `.env` и перезапустите контейнер. |

## Что видно в клиентских логах

Клиент v2rayN видит только первый hop:

```text
transport/internet/tcp: dialing TCP to tcp:banana.example.com:443
proxy/vless/outbound: tunneling request ... via banana.example.com:443
```

Это нормально. Внутренние hops `RU -> GE -> NordVPN` создаются Xray на
RU-сервере и не отображаются в логах клиентского приложения.

docker compose ps

docker compose run --rm bot bun index.ts --check
```

```
